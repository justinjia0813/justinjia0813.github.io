# 《调研之后：分析师如何找到自己的技术栈》文章设计

## 目标

承接《AI时代，分析师的能与不能》，讨论一个更进一步的问题：当 AI（Artificial Intelligence，人工智能，指用模型完成信息处理、生成与辅助推理）已经能够很好地胜任大量调研工作，分析师应当如何从真实业务瓶颈出发，建立能够加速其余工作的个人技术栈。

文章聚焦个人分析师的工作流，不扩展为整家投资机构的数字化方案，也不重复讨论人工智能能够或不能够替代哪些工作。

## 题目

**调研之后：分析师如何找到自己的技术栈**

## 核心判断

调研被很好地胜任，并不意味着分析师的工作消失，而是意味着瓶颈已经迁移。新的瓶颈在于：重要信息能否进入系统，会议、关系和项目进展能否持续留存，判断能否变成下一步行动，多个项目能否被稳定推进，以及一次项目经验能否降低下一次项目的认知成本。

因此，分析师不应继续优化已经不再稀缺的能力，也不应从不断尝试新工具开始建设技术栈。正确顺序是先找到工作流中新的瓶颈，再决定购买什么、连接什么和自行建设什么。

## 瓶颈识别方法

先还原完整工作流：

> 项目进入 → 初步判断 → 找人验证 → 访谈调研 → 更新模型 → 推进材料 → 跟踪任务 → 做出决策 → 等待结果 → 复盘

再识别其中四类摩擦：

1. **等待**：信息、反馈或协作长期停留在某个环节。
2. **搬运**：相同信息在聊天、笔记、表格和材料之间反复录入。
3. **丢失**：会议结论、人物关系、关键事实或判断依据没有进入可检索系统。
4. **遗忘**：项目结束后没有把结果与原始判断重新连接，经验无法形成下一次可用的规则。

技术栈的价值不以采用了多少新产品衡量，而以信息到行动的距离是否缩短、信息损耗是否减少，以及历史工作能否被复用衡量。

## 五层个人投资操作系统

1. **数据层**：统一保存公司、人物、行业、事件、证据、访谈和项目状态，让不同材料能够围绕同一对象连接。
2. **自动化层**：负责收集、归档、转写、分类、提醒和同步，减少重复搬运。
3. **智能层**：辅助检索、比较、总结、提出未知项和检查证据，但不替代分析师承担最终判断。
4. **行动层**：把判断转化为跟进问题、材料请求、专家访谈、内部协作、决策和持续跟踪。
5. **反馈层**：将后续事实与原始假设对照，把命中、误判和遗漏重新写入筛选规则、问题清单和行业认知。

五层不是五套彼此独立的软件，而是一条能够闭环的数据流。只有信息能够从数据进入判断、从判断进入行动、再从结果回到系统，技术栈才会形成复利。

## 项目示例

用一个投资项目贯穿全文：

> 项目进入 → 自动归档 → 形成公司与人物记录 → 调研结论进入证据库 → 访谈暴露新的未知项 → 自动生成跟进动作 → 分析师记录判断与触发条件 → 新事件持续对照原假设 → 结果回流到下一次筛选

具体展示以下环节：

- 项目材料进入后，系统识别公司、人物、赛道和融资信息。
- 公开调研先由人工智能处理，但同时保留来源和证据强度。
- 访谈记录与具体公司、人物、假设和待验证问题关联。
- 未知项转化为跟进、补充材料或寻找专家等明确动作。
- 投资或放弃时记录关键假设、价格、风险和触发条件。
- 后续新闻、融资、客户和经营变化持续与原始判断对照。
- 复盘结果更新筛选规则、访谈问题和行业认知。

最小可行闭环是：

> 访谈记录 → 待验证问题 → 跟进任务 → 结果回填

文章不主张从第一天建设完整系统，而是先打通一个真实、重复发生且可以验证价值的闭环。

## 购买、组合与自建

采用以下原则：

> 通用能力购买，流程连接组合，差异化资产自建。

- 已经标准化的通用能力直接购买，不为可替代功能重复开发。
- 跨工具的数据流和动作流通过轻量组合完成。
- 只有与个人判断方式、关系网络、历史决策和专属数据有关的差异化资产才值得自行建设。

选择工具时检查五个条件：问题是否高频重复，是否构成真实业务瓶颈，能否进入现有数据与流程，数据是否可导出并由用户控制，以及维护成本是否低于它节省的成本。

避免两种常见误区：为每一个新产品寻找使用场景，以及从第一天就建设完整操作系统。

## 文章结构

1. **调研不再是瓶颈**：承接上一篇文章，说明瓶颈已经迁移。
2. **技术栈不应从工具清单开始**：从业务摩擦而不是产品焦虑出发。
3. **重新拆解分析师的完整工作流**：找出调研之外尚未解决的环节。
4. **建立五层个人投资操作系统**：解释五层架构和闭环关系。
5. **让一个项目完整穿过系统**：用具体项目展示数据如何流动。
6. **购买、组合与自建的边界**：给出建设原则和工具筛选标准。
7. **下一代分析师，也是自己的系统设计者**：落到个人能力与职业分化。

## 表达方式

- 采用“个人观察 → 抽象方法 → 具体系统 → 职业判断”的连续论证。
- 语气克制，不把人工智能描述成万能替代者，也不写成软件采购指南。
- 产品只作为各功能层的少量例子；具体产品若进入正文，需要在写作时核验其当前能力。稳定框架优先于可能快速变化的产品名称。
- 首次出现英文缩写时给出英文全称、中文全称和一句简要解释。
- 不追求单纯节省时间或提高调研吞吐量，重点解释技术系统如何产生可积累、可复用的个人资产。

## 结尾判断

> 调研能力正在商品化，但组织调研、判断、行动和反馈的能力仍然稀缺。下一代优秀分析师，不只是人工智能的使用者，也会成为自己工作系统的设计者。

## 完成标准

- 与《AI时代，分析师的能与不能》形成自然承接，但不重复其能力边界论证。
- 全文围绕“从业务瓶颈寻找技术栈”推进，不退化为工具清单。
- 四类摩擦、五层系统和项目闭环能够帮助读者检查自己的实际工作流。
- 清楚说明购买、组合与自建的边界，并给出可以立即开始的最小闭环。
- 结尾落到个人系统的复利和分析师职业角色的变化。
- 不修改无关内容；本设计阶段不撰写正文、不发布网站。
